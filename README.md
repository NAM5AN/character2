# CHA LAB

캐릭터의 프로필과 오너의 답변을 바탕으로 성격, 관계 방식, 욕구, 두려움과 내적 모순을 단계적으로 해석하는 AI 캐릭터 분석 서비스입니다.

- 서비스: [cha-lab.com](https://cha-lab.com)
- 캐릭터 분석: [cha-lab.com/analyze](https://cha-lab.com/analyze)

> [!NOTE]
> 이 프로젝트는 **생성형 AI를 적극 활용해 제작 및 개발했습니다.** 아이디어 구체화, 구현, 코드 생성·수정, 코드 검토, 디버깅, 문서 작성과 반복 개선 과정에서 AI 도구를 사용했으며, 최종 선택·편집·테스트·통합·배포와 제품 및 디자인 결정은 프로젝트 관리자가 수행했습니다.

> [!IMPORTANT]
> 이 저장소는 **오픈소스 프로젝트이며 MIT License로 공개합니다.** 포크, 수정, 재배포, 직접 배포, 다른 프로젝트나 서비스에 활용하는 것 모두 가능합니다. 오류나 버그가 있으면 GitHub Issues, 사이트 내 `버그·오류·개선안 제보하기`, 또는 기존에 알고 계신 개인 연락처로 알려주셔도 되고, 별도로 문의하지 않고 직접 고쳐서 사용하셔도 됩니다. 상식적인 범위에서 자유롭게 알아서 활용해 주세요. 자세한 내용은 [LICENSE](./LICENSE)를 확인해 주세요.

## 주요 기능

- 공개 프로필·비밀 프로필 입력, 공개 문서 링크 불러오기, 외관 이미지 분석
- AI 해석에 대한 오너의 직접 검수와 성격 태그 보정
- 캐릭터별 맞춤 20문항 인터뷰 생성
- 초반에는 여러 성향을 넓게 탐색하고, 중반에는 새 주제와 후속 질문을 섞으며, 후반에는 앞서 드러난 중요한 포인트의 예외·임계점·모순을 다시 확인하는 적응형 질문 흐름
- 선택형, 척도형, 순위형, 관계별 반응표, 조건 변경형, 직접 입력형 등 다양한 답변 방식
- 작성 중인 캐릭터 분석 자동 저장, 이어하기, 이전 문항 확인·수정 및 이후 질문 재구성
- 성격 태그와 답변을 반영한 요약 리포트 생성
- 관계 패턴, 핵심 욕구와 두려움, 내적 모순을 다루는 상세 리포트와 페이지형 탐색
- 캐릭터별 테마 컬러가 적용된 공유 페이지와 색상 대비 자동 보정
- 공유 코드 기반 리포트 조회, 링크 공유, 캐릭터별 공유 메타데이터·OG 이미지
- 모바일 화면에 맞춘 프로필 이미지 입력, 인터뷰, 요약 카드, 상세 리포트, 페이지 이동·공유 UI
- 키보드·스크린리더 사용을 고려한 웹 접근성 개선
- 생성 상태, 실패·재시도 기록과 캐릭터 데이터를 관리하는 관리자 콘솔
- 사이트 내 버그·오류·개선안 제보 기능

## 접근성·반응형·품질 관리

CHA LAB은 마우스 사용을 전제로만 동작하지 않도록 키보드와 보조기술 사용성을 함께 개선하고 있습니다. 현재 구현에는 다음 항목이 포함되어 있습니다.

- `본문 바로가기` 링크와 전역 `:focus-visible` 포커스 표시
- 입력 필드의 시각적 라벨과 접근 가능한 이름 연결
- 상세 리포트 아코디언을 실제 버튼으로 구성하고 `aria-controls` 등 상태 정보를 제공
- 양극 척도형 질문에서 방향키, `Home`, `End` 이동과 roving tabindex를 지원
- 이용 코드 등 모달에서 열릴 때 포커스 이동, `Tab` 포커스 순환, `Escape` 닫기, 닫은 뒤 원래 버튼으로 포커스 복귀
- 생성 진행률을 `progressbar`와 `aria-valuenow`로 전달하고, 반복적으로 바뀌는 장식성 문구는 스크린리더에서 제외
- 캐릭터 포인트 컬러의 색조는 유지하면서 명도를 조정해 텍스트 4.5:1, 주요 그래픽 3:1 대비를 목표로 자동 보정
- 접근성 규칙을 포함한 ESLint 검사와 테마 대비 자동 테스트
- GitHub Actions `Verify`에서 lint, TypeScript 검사, 테스트, 프로덕션 빌드를 push와 Pull Request마다 실행

모바일에서는 단순 축소가 아니라 화면 구조와 터치 동작을 별도로 조정합니다. 외관 이미지 미리보기, 양극 척도형 질문, 요약 카드 그리드, 상세 리포트 스펙트럼·아코디언·페이지 이동·공유 버튼 등을 작은 화면에서도 사용할 수 있도록 반응형으로 구성하고 있습니다.

> [!NOTE]
> 위 항목은 현재 구현된 접근성 개선 사항을 설명한 것이며, 특정 접근성 인증이나 모든 환경에서의 완전한 준수를 의미하지는 않습니다. 문제가 발견되면 제보하거나 직접 수정해 사용해 주세요.

## 분석 흐름

1. 캐릭터 이름과 프로필을 입력합니다.
2. AI가 프로필의 사실과 성향을 구조화합니다.
3. 오너가 AI의 추론을 검수하고 성격 태그를 확정합니다.
4. 캐릭터에 맞춰 생성된 인터뷰에 답변합니다.
5. 답변을 바탕으로 요약 리포트를 생성합니다.
6. 필요한 경우 상세 리포트를 생성합니다.
7. 발급된 공유 링크에서 일반 사용자 화면으로 리포트를 확인합니다.

## 사용 설명서

### 1. 새 캐릭터 분석 시작

[캐릭터 정밀 분석](https://cha-lab.com/analyze)에서 아래 정보를 입력합니다.

| 항목 | 필수 여부 | 입력 방법 |
| --- | --- | --- |
| 캐릭터 이름 | 필수 | 최대 80자 |
| 공개 프로필 | 필수 | 직접 붙여넣기 또는 지원되는 공개 문서 링크 |
| 비밀 프로필 | 선택 | 직접 붙여넣기 또는 지원되는 공개 문서 링크 |
| 외관 자료 | 선택 | JPG, PNG, WEBP 이미지 최대 4장 |

공개 프로필은 최소 20자 이상이어야 하며, 공개·비밀 프로필은 각각 최대 20,000자까지 처리합니다.

프로필 입력칸에는 본문을 직접 붙여넣는 대신 다음 문서의 **공개 링크 하나만** 넣을 수도 있습니다.

- Google Docs
- Postype
- Notion

문서 링크를 사용할 때는 링크와 다른 문장을 섞지 않고 입력칸 전체에 URL만 넣어야 합니다. 문서가 외부에서 읽을 수 있도록 공개되어 있지 않으면 내용을 불러올 수 없습니다.

외관 자료는 파일 선택뿐 아니라 이미지를 복사한 뒤 `Ctrl+V`로 붙여넣을 수도 있습니다. 직접 첨부하는 이미지는 한 장당 10MB 이하이며 최대 4장까지 사용할 수 있습니다. 지원되는 문서 링크를 입력한 경우 문서 안의 이미지를 찾아 외관 자료로 자동 추가하기도 합니다.

> [!NOTE]
> 외관 이미지는 외형, 의상, 소품 등 시각적으로 확인 가능한 정보를 보조하는 자료로 사용됩니다. 이미지 한 장만으로 성격, 동기, 과거사나 관계 성향을 확정하도록 설계되어 있지 않습니다.

### 2. AI의 첫 해석 검수

`프로필 해석 시작`을 누르면 프로필과 외관 자료를 바탕으로 첫 해석을 만듭니다. 결과가 나오면 각 추론을 직접 확인합니다.

- **맞음**: 캐릭터 설정과 해석이 맞는 경우
- **애매함**: 일부만 맞는 경우. 맞는 부분과 다른 부분을 추가로 적을 수 있습니다.
- **아님**: 실제 캐릭터와 다른 경우. 실제 설정이나 행동을 직접 보충할 수 있습니다.

같은 화면에서 AI가 프로필을 기준으로 성격 태그를 먼저 제안합니다. 맞지 않는 태그는 빼고 필요한 태그는 추가할 수 있으며, 최대 8개까지 선택할 수 있습니다. 이 선택은 이후 질문과 리포트의 보조 정보로 사용됩니다.

검수를 마치면 `20문항 인터뷰 시작`을 눌러 다음 단계로 이동합니다.

### 3. 20문항 인터뷰 답변

인터뷰는 총 20문항이며 캐릭터 프로필, 앞선 답변과 분석 상태를 바탕으로 순서대로 생성됩니다. 질문에 따라 보기 선택, 직접 입력, 척도, 복수 선택, 순위 지정, 상황 비교 등 서로 다른 답변 방식이 표시될 수 있습니다.

질문 흐름은 한 가지 특징만 계속 파고들지 않도록 구성되어 있습니다. 초반에는 캐릭터의 서로 다른 면을 폭넓게 확인하고, 중반에는 새 주제 탐색과 이전 답변의 후속 질문을 섞으며, 후반에는 앞에서 정보가치가 높았던 답변을 다시 가져와 예외·조건·모순이나 임계점을 더 깊게 확인합니다. 파고들기는 반드시 직전 답변에서만 이어지지 않으며, 몇 문항 전에 나온 중요한 답을 다시 연결할 수도 있습니다.

각 문항의 `왜 그렇게 답했나요?` 항목은 선택 사항입니다. 선택지만으로 설명하기 어려운 조건이나 예외가 있다면 추가로 적을 수 있습니다.

이전 질문으로 돌아가 답변을 확인하거나 수정할 수도 있습니다. 다만 **과거 답변을 수정한 경우 그 이후 문항의 답변과 질문은 수정된 내용에 맞춰 다시 이어지도록 재구성될 수 있습니다.**

작성 중인 분석 상태는 현재 브라우저에 자동 저장됩니다. 분석 페이지에 다시 들어왔을 때 저장된 진행 상태가 있으면 `이어하기`와 `처음부터 하기` 중에서 선택할 수 있습니다.

### 4. 요약 리포트 생성

20문항을 모두 답하면 요약 리포트 생성을 시작합니다. 캐릭터 프로필, 첫 해석에 대한 오너 검수, 성격 태그와 20개 답변을 함께 반영합니다.

생성 중에는 실제 처리 진행률이 표시됩니다. 현재 화면 안내 기준으로 약 3~5분이 걸릴 수 있으므로 생성이 끝날 때까지 창을 닫지 않는 것을 권장합니다.

완료되면 캐릭터별 요약 리포트와 8자리 공유 코드가 생성되며, 해당 캐릭터의 고유 리포트 주소로 연결됩니다.

### 5. 캐릭터 저장과 다시 불러오기

리포트를 처음 만든 브라우저에서는 요약 리포트 상단의 `캐릭터 저장` 영역에서 오너명을 입력해 저장할 수 있습니다.

- 캐릭터 이름과 오너명 조합으로 나중에 리포트를 다시 찾습니다.
- 같은 **캐릭터 이름 + 오너명** 조합은 중복 저장할 수 없습니다.
- 오너명 저장·변경 권한은 캐릭터를 생성한 브라우저에 보관됩니다.
- 오너명은 공개 리포트 미리보기 정보에서는 제외됩니다.

저장한 캐릭터를 다시 열 때는 메인 화면의 `이미 분석한 캐릭터가 있나요?`에서 캐릭터 이름과 오너명을 입력합니다. 일치하는 캐릭터가 있으면 해당 캐릭터의 고유 공유 코드 주소로 이동합니다.

> [!TIP]
> 생성자 편집 권한과 작성 중인 분석 상태는 브라우저 저장소를 사용합니다. 사이트 데이터를 삭제하거나 시크릿 모드를 사용하거나 다른 기기로 이동하면 이어하기 상태, 저장된 이용 코드 또는 생성자 편집 권한을 그대로 사용할 수 없을 수 있습니다.

### 6. 상세 리포트 보기

요약 리포트 아래의 `더 자세히 보기`를 누르면 상세 리포트를 열 수 있습니다. 아직 상세 리포트가 생성되지 않은 캐릭터는 Postype에서 최신 이용 코드를 확인한 뒤 입력해야 합니다. 정상 확인된 이용 코드는 현재 브라우저에 저장됩니다.

상세 리포트는 관계에서 반복되는 패턴, 핵심 가치·욕구·두려움, 내적 모순, 애착과 갈등 방식, 강점과 취약점, 캐릭터 사용 설명서, 통합 상세 해석 등을 여러 영역으로 나누어 보여줍니다. 현재 형식에서는 상세 리포트를 3페이지로 나누어 볼 수 있으며, 첫 페이지가 준비된 뒤 나머지 페이지를 이어서 준비합니다.

상세 섹션은 접고 펼칠 수 있으며 키보드로도 조작할 수 있습니다. 모바일에서는 스펙트럼, 접기/펼치기, 페이지 이동과 공유 동작이 작은 화면에 맞게 배치됩니다.

처음 상세 리포트를 생성하는 과정에서는 캐릭터를 만든 브라우저의 생성자 권한이 필요할 수 있습니다. 이미 상세 리포트가 생성되어 저장된 경우에는 이후 접속에서 저장된 결과를 다시 불러옵니다.

### 7. 리포트 공유

요약 리포트와 상세 리포트의 `공유하기`를 통해 `/character/공유코드` 형식의 고유 주소를 공유할 수 있습니다. 기기에서 시스템 공유 기능을 지원하면 공유 창도 함께 열 수 있습니다.

캐릭터 공유 페이지에는 캐릭터별 메타데이터와 공유용 OG 이미지가 생성되어 링크 미리보기에서도 캐릭터 리포트임을 확인할 수 있습니다.

공유 링크를 받은 사람은 같은 캐릭터 리포트 페이지를 열 수 있습니다. 공개 프로필뿐 아니라 비밀 프로필도 분석 근거로 사용되므로, **비밀 설정을 바탕으로 한 해석이 리포트 결과에 반영될 수 있습니다.** 링크를 외부에 공유하기 전에는 결과 내용을 먼저 확인하는 것을 권장합니다.

## 기술 구성

| 영역 | 기술 |
| --- | --- |
| 웹 애플리케이션 | Next.js 16, React 19, TypeScript |
| AI 연동 | Vercel AI SDK, Vercel AI Gateway |
| 데이터베이스 | Supabase Postgres, RPC, RLS |
| 검증 | Zod |
| 접근성 검사 | ESLint `jsx-a11y`, 키보드 수동 점검, 테마 대비 자동 테스트 |
| CI | GitHub Actions `Verify` — lint, TypeScript, test, build |
| 배포 | Vercel |

## 로컬 실행

### 요구 사항

- Node.js 20 이상
- npm
- Supabase 프로젝트 또는 개발용 연결 정보
- AI 모델을 호출할 수 있는 로컬 또는 배포 환경

### 설치

```bash
git clone https://github.com/NAM5AN/character2.git
cd character2
npm install
```

`.env.example`을 `.env.local`로 복사한 뒤 개발 환경에 맞는 값을 설정합니다.

```bash
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

## 환경변수

| 변수 | 용도 | 공개 가능 여부 |
| --- | --- | --- |
| `OPENAI_MODEL` | 프로필 구조화 등에 사용할 모델 재정의 | 서버 설정 권장 |
| `ANTHROPIC_MODEL` | 리포트 생성 등에 사용할 모델 재정의 | 서버 설정 권장 |
| `SUPABASE_URL` | Supabase 프로젝트 URL | 공개 가능 |
| `SUPABASE_PUBLISHABLE_KEY` | Supabase 공개 클라이언트 키 | 공개 가능 |
| `CHARACTER2_TELEMETRY_SECRET` | 서버의 AI 사용 기록 RPC 인증 | 비공개, 서버 전용 |
| `RATE_LIMIT_SALT` | 요청 IP 해시용 추가 salt | 비공개, 서버 전용 |

운영 환경에서는 Vercel AI Gateway OIDC를 사용합니다. 실제 비밀값은 저장소에 커밋하지 말고 Vercel 또는 로컬의 `.env.local`에서 관리해야 합니다.

## 명령어

```bash
npm run dev      # 개발 서버
npm run build    # 프로덕션 빌드
npm run start    # 프로덕션 서버 실행
npm run lint     # ESLint + 접근성 규칙 검사
npm run test     # Node 테스트 실행
npx tsc --noEmit # TypeScript 타입 검사
```

## 디렉터리 구조

```text
src/app/          페이지와 API 라우트
src/components/   분석, 질문, 리포트 UI
src/lib/          AI, 데이터, 인증 및 공통 로직
supabase/         데이터베이스 마이그레이션
test/             자동화 테스트
public/           정적 파일
```

## 데이터와 보안

- 서비스 데이터는 `character2_*` 이름 공간으로 분리합니다.
- 브라우저에서 주요 테이블을 직접 조작하지 않고 제한된 RPC와 서버 API를 사용합니다.
- 데이터 접근은 Supabase RLS와 서버 측 검증을 전제로 합니다.
- 관리자 세션, 서버 전용 secret, 이용 코드와 운영 설정을 클라이언트 코드에 노출하지 않습니다.
- 실제 사용자 데이터나 운영용 환경변수를 이 저장소에 커밋하지 않습니다.

`main` 브랜치는 Vercel 프로덕션 프로젝트와 연결되어 있습니다. 원격 `main`에 반영된 변경은 GitHub Actions의 검증과 Vercel 프로덕션 빌드를 거쳐 [cha-lab.com](https://cha-lab.com)에 배포됩니다.
